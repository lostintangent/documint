# Anchors

The anchors subsystem owns editor-side runtime support for the document anchor algebra. The document layer defines the content-addressable vocabulary and search primitives. This layer resolves those anchors into editor runtime state, layout, and viewport behavior.

Anchors sit alongside the editor pipeline rather than inside one stage. They keep comments, presence, and other anchored data attached to the current document snapshot as content changes.

## Design Principles

- **Document owns the algebra, editor owns runtime resolution.** Anchor vocabulary and semantic resolution live in `src/document`. This subsystem maps matches to editor paths, ranges, cursors, and viewport statuses.
- **Node anchors resolve to document and editor paths.** Document node anchors prove a block or table cell match across snapshots. Editor node anchors keep the matched document path separate from the editor path a selection or effect should target, so block-level consumers do not accidentally collapse into descendant-cell identity.
- **Selection anchors recover offsets, not external trust.** `SelectionAnchor` is an editor-owned, ephemeral anchor for a selection point. It composes document text-anchor context with selection affinity, a fallback offset, and text-continuity checks over runtime editor text. Component sync decides when an external snapshot is trustworthy enough to reuse that recovered offset.
- **Anchors are not selections.** Anchor offsets are semantic container offsets. Editor selections are editor text-path offsets. Convert deliberately at the boundary.
- **Anchor containers resolve through paths.** Document anchor matches carry the current snapshot's container path; editor resolution maps that path to block or table-cell editor text.
- **Carried matches keep typing cheap and comments on repeated text in place.** Content-addressable resolution walks the whole document and can't tell identical quotes apart, so each reducer commit carries every thread's match forward from the previous snapshot instead. A match in the edited path is remapped through the edit's offsets. Elsewhere, a prior match counts only where node identity proves its location: its node is the same object in both snapshots, even after a structural edit such as an inserted table row or list item moves it. Finding a moved node indexes only the roots the commit changed, so typing never pays for it. That match is reused while the thread still anchors there, and otherwise only breaks ties when the thread re-resolves. Identity is proof because a Document never holds one node object twice (see [`../state`](../state/AGENTS.md)). An unproven prior never steers resolution, so carry can hide a comment but never move it onto another copy of its text. Threads that don't resolve re-resolve at every commit, since an edit can bring their text back.
- **A saved occurrence reopens comments on repeated text where they were.** Carry tells identical copies apart only within a session, so each commit also keeps `anchor.occurrence` in the committed Document: which full-context copy, in document order, the comment sits on. A reload's cold read breaks its tie with that count. A recount walks the whole document, so `comments/occurrence.ts` recounts only when a copy may have appeared or vanished around the thread: a changed container holds or held a copy other than the thread's own match, or its anchor changed. A moved match doesn't recount by itself, because every command that moves content shifts everything it moves past, so a match never crosses a container that keeps its path. A command that breaks this, such as a drag that moves a list item past an untouched list, has to make a moved match recount again and add a scenario row that proves it. A thread whose quote and context are unique in the document drops its hint without a recount. Cold reads never write hints, since their records are keyed by the Document they read. A count that doesn't land on a full-context copy fails closed, so a reload can hide a comment but never move it. A thread that only re-resolved through a partial-context tie keeps that repair in state, so it can show live and hide after a reload.
- **Comment records belong to the Document they describe.** Each snapshot's matches live in a write-once table keyed by `Document`, outside the immutable snapshots. That is a deliberate exception to answering purely from snapshot inputs: a record depends on the commit that produced its Document, not only on the Document. In return, `getCommentState(documentIndex)` keeps its signature, selection moves keep their records, and undo and redo restore them along with the Documents they bring back. Documents no commit produced, such as parsed markdown or host snapshots, resolve cold on first read.
- **A retyped comment keeps covering what replaced it.** An edit that deletes a comment's last character opens its end, so text typed right there extends the comment. Retyping "world" as "planet" leaves the comment on "planet", not "p". Any other commit closes the end. The open end lives on the record, so undoing to the middle of a retype reopens it.
- **Unresolved is a valid state.** Presence targets and comment ranges may fail to resolve against the current snapshot; callers should preserve source data and omit only the runtime result.

## Subsystem Map

- `index.ts` owns public re-exports.
- `text.ts` owns editor resolution of document text-anchor containers into editor paths and runtime ranges.
- `nodes.ts` owns editor resolution of document node anchors into matched document and editor paths.
- `selection.ts` owns editor selection anchors, which recover runtime offsets and text continuity from document text-anchor context plus selection affinity.
- `comments/` owns comment capture, viewport geometry, and active-thread lookup.
- `comments/carry.ts` owns each snapshot's comment records and carries them across reducer commits.
- `comments/occurrence.ts` owns keeping each thread's saved occurrence in step with the copies around it.
- `presence/` owns the host `DocumentUser` and `DocumentPresence` inputs, presence target resolution, and viewport mapping.
