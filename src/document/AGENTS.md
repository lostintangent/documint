# Document

The document subsystem gives every layer one format-agnostic `Document` model for editable content, so markdown round-trips, editor commands, rendering, comments, and presence all target the same semantic truth. A `Document` is a closed immutable tree of semantic block and inline nodes with plain-text projections, structural path queries, and anchored annotations. That shared model is what lets undo/redo share unchanged structure, comments survive edits, and search reason about user-visible text instead of markdown syntax or rendering artifacts.

## Design Notes

- **A closed typed model keeps every layer speaking the same language.** Blocks, inlines, marks, resources, and comments are closed model shapes with exhaustive unions where the schema branches. New content concepts should become typed variants, not editor-specific side channels. `frontMatter` is the one format-specific exception: document code preserves it as an opaque markdown round-trip slot but does not interpret it.
- **Canonical builders keep semantic snapshots small and shareable.** Builders create semantic node shapes with derived fields such as `plainText`, canonical marks, and default values. `createDocument` and `spliceDocument` preserve block object identity outside the edited range and seal only document-level metadata such as comment-thread IDs, so runtime addressing stays out of the semantic tree.
- **Structural paths and anchors name nodes without becoming node fields.** Paths are snapshot-local coordinates used by queries, editor indexes, and diff targets, while anchors describe content-addressable matches across rebuilt snapshots. `model/paths.ts` is the only place that parses path strings; other code composes named path operations such as parent lookup, containment, root rebasing, and table-cell position lookup. Semantic block and table-cell nodes do not carry runtime IDs, so callers must choose path lookup, reference equality, or anchor matching according to the meaning they need.
- **Shared text queries keep semantic reads consistent.** Cached `plainText` strips away markdown syntax so search and anchors reason about the document users recognize. Runtime editor offsets are not a document concept: references can occupy one editor selection unit while contributing semantic text such as alt text, labels, or mention names to `plainText`.
- **Node anchors recognize whole nodes across rebuilt snapshots.** A `DocumentNodeAnchor` combines a content hash with weak structural context for a whole block or table cell. It helps higher layers match freshly parsed host snapshots without treating snapshot-local IDs or paths as durable anchors. Node anchors are matching descriptions, not identity: same-path exact content can match by location, context-free anchors can match unique moved content, and context-bearing moved content needs matching context so collapsed duplicates fail closed.
- **Document diff owns bounded change matching.** `diff/` detects semantic additions and modifications between immutable snapshots, then describes targets with node anchors plus last-seen paths for higher-layer sync to verify or retarget. It is not a complete edit-script engine. Ambiguous or over-budget matching returns no target rather than guessing.
- **Content-addressable anchors make annotations survive edits.** Anchor algebra describes positions by semantic text containers and surrounding content, not editor runtime offsets or snapshot IDs. Paragraphs, headings, code blocks, and table cells can be anchor containers. Anchor container matches report the current snapshot's structural path so editor consumers can map the match to editor path text; the path is a location hint, not the durable reason the anchor matched. Aggregate `plainText` on lists, blockquotes, tables, directives, raw blocks, or dividers is deliberately not one. Editor consumers convert anchor matches to runtime offsets at the boundary.
- **Comments and fragments stay at their own altitude.** Comment threads live on `Document.comments`, store content-addressable anchors plus quoted text, and keep thread CRUD plus matched/repaired/ambiguous/stale resolution policy in `comments/`. Clipboard `Fragment`s carry text, inline, or block payloads without comments or front matter. Markdown owns fragment conversion, and the editor owns insertion policy.

## Subsystem Map

- `index.ts` owns the public document facade and re-exports only the surfaces that cross the document boundary.
- `model/` owns the closed semantic schema, structural path vocabulary, block content classification (`blockContentKind`), structural-container access, mark canonicalization, resource protocol helpers, and document node types.
- `build/` owns semantic builders, canonical document construction, root-level splicing, document-level comment splicing/id sealing, no-op-aware canonicalization, and `plainText` ownership.
- `query/` owns traversal, lookup, tree mapping, semantic plain-text projection, reference classification, content-addressable anchor primitives, and document node anchors.
- `diff/` owns bounded document-change detection, target anchors, and location keys for document changes.
- `comments/` owns persisted comment-thread shape, immutable thread mutations, defensive parsing, deterministic thread IDs, and comment-specific anchor resolution policy.
