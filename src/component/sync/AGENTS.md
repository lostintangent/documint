# Component Sync

Component sync lets embedders connect Documint to markdown files without making React props the live editing buffer. A `DocumentView` resolves host props into either a live document or a fixed snapshot comparison, then document sync applies that view to editor state and emits local markdown snapshots back to the host. Editor selection, editing semantics, networking, conflict resolution, and presence transport stay with their owning layers.

## Design Notes

- **Full snapshots keep persistence simple.** Local content edits synchronously serialize the live runtime document and pass the full next markdown string to `onContentChanged`. That snapshot is a host notification for saving, transport, conflict handling, and text diffs, not a request to feed the same markdown back through the `content` prop.
- **Markdown ranges are not editor truth.** Component sync does not maintain source maps, root offset tables, patch bases, or incremental markdown projections just to describe changes as ranges. The editor owns editing semantics, and full snapshots remain the host-facing interchange format until measured cost or a consumer-proven API justifies incremental projection.
- **Document views keep host presentation policy coherent.** `useDocumentView` parses host markdown and derives one discriminated live or snapshot view. The view owns the document to display, effective body read-only policy, comment mutation policy, active-block highlight visibility, review chrome visibility, and diff visibility so `Documint` does not reinterpret mode through parallel booleans.
- **External snapshots replace editor state atomically.** `useDocumentSync` builds one fresh editor state from the resolved view, repairs selection when it can, and publishes the result through `store.editor.replace`. External replacements publish `source: "external"`, so Documint does not echo host-applied snapshots back through `onContentChanged`.
- **String-equal live snapshots are no-ops.** In live mode, sync applies host markdown only when `content` or parser options change. Entering snapshot mode is the deliberate exception: sync reapplies the authoritative current content so local drift cannot be compared against the wrong document. Sync does not keep local-emission history or revision tokens, so hosts should update `content` only for external file or network changes instead of treating Documint as a controlled text input.
- **Live changes and snapshot comparisons have distinct lifecycles.** Without `previousContent`, sync keeps added and modified external nodes as acknowledgeable live state. With `previousContent`, the view contains a complete comparison document and persistent `DocumentChange` values, including deletions. Snapshot mode disables body and comment editing. `showDiffs` hides and skips either kind of change display without changing snapshot read-only policy.
- **Best-effort reconciliation preserves continuity without owning conflicts.** Selection repair may use stable editor paths only when backed by an anchor/content match: document-node anchors, path plus selection-anchor context, exact projected text, or nearby root anchors. Component sync owns this external snapshot trust order. Editor anchors only answer whether an anchor can resolve against runtime editor text. Ambiguous structural rewrites still apply the host markdown snapshot, but sync skips speculative caret repair instead of merging competing edits or deciding document truth.
- **Unacknowledged document changes are live-only lifecycle state.** Sync keeps bounded additions and modifications only when their `DocumentChange` anchor still matches the current document, retargeting that anchor through editor resolution as the document moves. Newly observed changes are reported separately from retained changes, and retained changes add only a stable `changeKey` so the renderer can animate introductions once. Snapshot changes bypass this machinery because their anchors already belong to the complete comparison document.
- **Mention events give hosts the changed markdown line.** Mention events report the canonical changed markdown line because embedders need that exact line content. The helper serializes the document before and after the mention and reports the first line that differs, so the line number matches the `onContentChanged` snapshot even when a block spans several lines, such as a paragraph with soft breaks.

## Subsystem Map

- `useDocumentView.ts` owns the prop-derived document, live or snapshot mode, and interaction policy.
- `useDocumentSync.ts` owns the effectful bridge: host callbacks, editor-state replacement, live-change lifecycle, and snapshot entry synchronization.
- `live-changes.ts` owns unacknowledged change merging, anchor retargeting, selection dismissal, and new-change reporting.
- `selection/` owns selection continuity across external snapshots: public orchestration, editor-path trust policy, and editor-only empty root repair.
- `mention-event.ts` owns accepted mention edits to canonical markdown-line payloads for embedders.
- `index.ts` owns the public component-sync surface exported to neighboring component code.
