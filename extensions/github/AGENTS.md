# GitHub Copilot Canvas Extension

The GitHub extension adds a Documint canvas to GitHub Copilot, so a user can edit a markdown file beside a Copilot session and hand work to Copilot by mentioning @Copilot in a comment or on a line of the document. The parent session's agent can also read the file, replace it, or start a job through canvas actions. `extension.mjs` is the extension process. It keeps one _document_ per markdown file, whose `revision` counts its changes, serves the app over local HTTP, and runs Copilot _jobs_ in worker sessions. `src/app.tsx` is the browser app that mounts Documint in each canvas _instance_, identified by `instanceId`.

## Design Notes

- **The file on disk is the document, so the canvas, Copilot and other editors converge on it.** Documents are keyed by absolute path, so canvases on the same file share one document, one watcher and one set of event stream subscribers. Every change lands on disk first, then bumps `revision` and goes out on `/events`, which opens with the full `state` and then sends `content`, `job` and `error` events. Outside edits arrive through a debounced `fs.watch`, and the server also rereads the file before each save, each new stream, and each worker tool call the revision gate checks. When that reread fails as a stream opens, the server still opens the stream with the cached state, since an error status would close the browser's `EventSource`. The app also recreates a closed stream, backing off from 250ms to 5s.
- **Ordered snapshot saves keep canvases in step without overwriting changes they haven't shown.** The app queues each full markdown snapshot as a `PUT`, with the `baseRevision` of the content Documint had applied when the edit happened. It records that revision in a layout effect that runs after Documint's, so an edit that lands before new content renders still names the older one. A successful save goes out to every other canvas but skips the one that sent it, matched by `clientId`, since Documint treats a new `content` prop as an external replacement (see [`src/component/sync`](../../src/component/sync/AGENTS.md)). That canvas never hears its own saves, so the server accepts a save when every revision after its base came from the same canvas. Otherwise it answers 409 with the latest state, rereading the file first so a disk change counts, and the app swaps in that content and remembers the conflict.
- **Mentions become Copilot jobs that answer in the same file.** A comment that mentions @Copilot, a reply in a thread that already did, or a document line that mentions it starts a job. The app first waits for its pending saves and refuses if the last one conflicted, so Copilot reads what the user sees. Each job runs in its own worker session in autopilot, with every permission approved and the parent session's working directory. Its prompt carries the thread or line and the parent session's ID and workspace path, plus, for comments, a rubric for choosing between editing the body, replying, or doing nothing. Replies go into the trailing `:::documint-comments` directive (see [`src/markdown`](../../src/markdown/AGENTS.md)), so canvases pick them up like any other edit. While a job runs, the app shows Copilot as a presence at the mention or thread, with status text from the worker's intent and reasoning events.
- **The revision gate keeps Copilot from writing over edits it hasn't read.** As each worker tool call that touches the file starts, the gate classifies it as a read or write from the tool name, its path arguments, or simple shell patterns, and rereads the file. A read records the current revision. A write is denied, with a reason telling the worker to reread, when the revision has moved since the worker's last read, so a write based on an older read is turned away. The check runs before the tool does, so an edit that lands while a write runs can still be lost. After a successful write the gate rereads the file and counts the new revision as read.
- **Route checks keep each request scoped to its document.** The server listens on a random `127.0.0.1` port and serves any request that names an open instance. Storage reads must resolve inside the document's directory, pasted images go to `assets/` beside the document under a timestamped, sanitized name, request bodies are capped at 25 MB, and the Copilot routes recheck the mention before starting a job.
- **`extension.mjs` ships as plain source, so it shares no code with the app.** The Copilot runtime loads it directly with no build step or types, and supplies `@github/copilot-sdk`. Only the app is bundled, into `dist/app.js`, and opening a canvas fails until that bundle exists. `src/types.ts` mirrors the parts of the server's payloads the app reads, by hand, so a payload change updates both sides.

## Known Limitations

- **The revision gate recognizes tools by name and shell writes by pattern.** A shell write it doesn't recognize, or a tool that doesn't name the file in a path argument, skips the gate. The prompt steers the worker toward file editing tools, which the gate does recognize. If workers start overwriting user edits, gate on file changes instead of tool names.

## Subsystem Map

- `extension.mjs` owns the canvas definition and actions, documents and file watching, the local server and its routes, the event stream, Copilot jobs and their prompts, the revision gate, and storage.
- `src/app.tsx` owns the canvas app: document state and the save queue, Copilot triggers and presence, and the `Documint` mount with the status line that shows errors once a document has loaded.
- `src/types.ts` owns the app's copy of the server's state, job and event payloads.
- `src/hooks/useServerEvents.ts` owns the event stream connection and its reconnect backoff.
- `src/hooks/useStorage.ts` owns the `DocumintStorage` adapter over the storage routes.
- `src/hooks/useTheme.ts` owns the mapping from the canvas page's GitHub theme variables and color mode to `EditorTheme`, including Copilot's purple mention colors.
- `package.json` owns the app build. The root `github:install` script copies this folder into `~/.copilot/extensions/documint`.
